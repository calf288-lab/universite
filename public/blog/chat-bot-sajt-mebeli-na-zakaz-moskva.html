Чат-бот для сайта мебели на заказ в Москве: как увеличить заявки с 1,2% до 3,5%

Проблема: форма «Оставить заявку» теряет горячих посетителей

Для мебельного салона на заказ в Москве типовая ситуация выглядит так:

  • 5000 посетителей сайта в месяц.
  • 1,2% конвертируются через форму.
  • 60 заявок в месяц.
  • Средний чек 250 000 ₽.
  • Рекламный CPL 2000 ₽.

Форма предлагает посетителю сделать действие, которое требует усилий: оставить телефон, дождаться звонка, объяснить задачу менеджеру.

Для мебели на заказ это особенно критично. Посетителю часто нужна не просто консультация. Он хочет понять порядок цены прямо сейчас.

Например, человек ищет кухню 4,5 метра в Москве. Он не готов оставлять телефон, пока не понимает, будет ли проект стоить 180 000 ₽, 300 000 ₽ или 700 000 ₽.

В результате рекламный трафик оплачивается, посетитель изучает каталог, смотрит проекты, после чего закрывает сайт.

Экономика потерь

При 5000 посетителей и CPL 2000 ₽ рекламный бюджет, связанный с таким объёмом платного трафика, составляет условные 10 млн ₽.

Это модельный расчёт, а не гарантия результата. Фактическая конверсия зависит от качества трафика, ассортимента, цен, оффера, скорости ответа менеджеров, доверия к бренду.

При CPL 2000 ₽ каждая дополнительная заявка имеет понятную стоимость привлечения.

Если бот увеличивает количество заявок с 60 до 175 при том же объёме трафика, стоимость привлечения одной заявки в рамках рекламной модели снижается с 1667 ₽ до 571 ₽.

Ключевой показатель для сайта мебельной компании — это не просто количество посещений. Важно, сколько посетителей начали диалог, рассчитали проект, передали контакты менеджеру.

Архитектура решения

ИИ-чат-бот для мебельного сайта должен быть не виджетом с приветствием «Здравствуйте, чем могу помочь?». Такой сценарий почти не отличается от обычного онлайн-чата.

Для мебели на заказ нужен сценарий предварительной квалификации с расчётом ориентировочной стоимости.

1. Определение задачи

Бот начинает с понятного выбора: «Что планируете заказать?» (кухня, шкаф, гардеробная, гостиная, мебель для спальни, мебель для коммерческого помещения). Посетителю не нужно самостоятельно формулировать техническое задание.

2. Сбор параметров

Далее бот задаёт короткие вопросы. Для кухни: длина кухни, конфигурация, материал фасадов, тип столешницы, количество рабочих зон, техника, желаемый бюджет. Необязательно спрашивать всё сразу. Задача первого диалога — получить параметры, достаточные для предварительной оценки.

3. Расчёт ориентировочной стоимости

После ответов бот показывает диапазон. Например: «По указанным параметрам ориентировочная стоимость кухни составляет 280 000–360 000 ₽». Важно использовать именно ориентировочную стоимость. Бот не должен выдавать её за финальную смету, если точный расчёт требует замера, проекта или консультации технолога.

4. Перевод расчёта в заявку

После получения цены появляется логичный следующий шаг: «Хотите получить точный расчёт от специалиста?» Дальше бот запрашивает имя, телефон, удобное время связи, при необходимости — адрес объекта. Контакт появляется после получения пользы, а не до неё. Это принципиальная разница между обычной формой и калькулятором в формате диалога.

5. Передача данных менеджеру

Менеджер получает не просто номер телефона. CRM может получить структурированную заявку: тип мебели, длина, фасады, столешница, техника, ориентировочный бюджет, имя, телефон. Менеджеру не приходится начинать разговор с вопроса «Расскажите, что вас интересует?» — он уже видит контекст.

Что меняется в воронке

Классическая схема: Реклама → Сайт → Каталог → Форма → Звонок менеджера. Проблема находится между сайтом и формой. Посетитель должен самостоятельно принять решение оставить контакт.

С чат-ботом появляется промежуточный этап: Реклама → Сайт → ИИ-бот → Вопросы → Ориентировочная стоимость → Контакт → CRM → Менеджер. Бот становится частью конверсионной архитектуры сайта. Он не заменяет менеджера. Он собирает первичные данные, отвечает на типовые вопросы, квалифицирует посетителя.

Внедрение на сайт мебельной компании

Внедрение не должно начинаться с программирования. Сначала формируется логика продаж.

Этап 1. Анализ текущей воронки

Проверяются источники трафика, посадочные страницы, конверсия форм, стоимость привлечения, популярные категории мебели, глубина просмотра, страницы выхода, заявки из разных рекламных каналов. Главная задача — определить места, где посетитель уже проявляет коммерческий интерес, но не оставляет заявку.

Этап 2. Проектирование сценария

Создаётся дерево диалога. Например: Кухня → Размер → Конфигурация → Материалы → Столешница → Техника → Бюджет → Ориентировочная стоимость → Получить точный расчёт → Контакт. Отдельно формируются сценарии для вопросов по срокам, доставке, монтажу, гарантии, материалам, рассрочке, замеру, готовым проектам.

Этап 3. Подключение расчётной логики

Бот получает правила расчёта: базовая стоимость + погонные метры + фасады + столешница + фурнитура + техника + дополнительные работы. Конкретные коэффициенты зависят от прайса компании. При изменении цен расчётная модель должна обновляться без полного переписывания сценария бота.

Этап 4. Подключение CRM

Заявка передаётся в CRM вместе с историей диалога. Это позволяет отделу продаж видеть, что клиент выбирал, какой бюджет указал, какую стоимость получил, какие вопросы задавал, какие контакты оставил.

Этап 5. Аналитика

Нужно измерять не только количество чатов. Минимальный набор событий: chat_open, chat_start, category_selected, parameters_completed, price_shown, lead_started, lead_submitted, crm_created, manager_contacted, deal_created, deal_won. После этого можно считать реальные показатели: конверсия сайта, конверсия бота, конверсия в продажу, стоимость заявки, стоимость продажи. Последний показатель важнее самой конверсии.
